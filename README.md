##Реалізація парадигм ООП (Варіант 3)

Проєкт побудовано з чітким дотриманням архітектурних вимог:

| Парадигма | Опис реалізації в коді |
| :--- | :--- |
| **Абстракція** | Базовий клас `Product` виносить загальні поля (`name`, `price`, `quantity`) та визначає обов'язковий абстрактний метод `get_info()`. |
| **Наслідування** | Класи `Electronics` (додає `warranty_years`) та `FoodItem` (додає `expiry_days`) наслідують структуру базового продукту. |
| **Поліморфізм** | Метод `get_info()` викликається динамічно для будь-якого об'єкта у кошику, повертаючи специфічні дані у своєму унікальному форматі. |
| **Інкапсуляція** | Сховище товарів `__inventory` всередині класу `Store` є строго приватним (`private dictionary`) та захищеним від прямого зовнішнього втручання. |

---

## 🛠 Інструменти та Логіка Агента (`No-API Mode`)
* **Tool (Інструмент):** Функція `get_product_price(product_name: str)` локально ініціалізує об'єкт магазину `Store`, наповнює його тестовою номенклатурою товарів та повертає структурований словник із даними.
* **Агент (`store_consultant`):** Інтелектуальний модуль, який аналізує текстовий промпт користувача українською мовою, розпізнає сутність товару, викликає відповідний ООП-інструмент та формує персоналізовану відповідь.
